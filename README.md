# 知乎内容医生

一个面向知乎创作者的内容诊断与账号定位 Skill。

它不是批量生成回答的写作模板，也不是教人堆砌“爆款技巧”。它更关心的是：这个选题值不值得写、草稿是否真正回答了问题、观点能否站得住，以及一篇内容怎样沉淀为长期的专业资产。

## 它能做什么

- 判断选题是否适合当前账号，而不只看表面流量
- 比较“回答已有问题”和“发布独立文章”哪种方式更合适
- 诊断开头、观点密度、结构、论证和知乎调性
- 删除教科书腔、公众号腔、小红书腔和短视频口号感
- 识别逻辑跳跃、绝对化结论、因果倒置和无来源数字
- 把个人经历提炼成可迁移的行业洞察，而不是经历流水账
- 将同一母题重构为知乎回答、知乎文章、朋友圈引言等载体
- 为长期账号定位提供选题与分发建议

## 核心原则

> 不是卖教程，而是提供判断。

内容需要帮助读者看清变量、条件、取舍和风险。真实经历可以成为证据，但不能自动升级为普遍规律；未经核验的数据、结果和身份不能被补写。

当用户的观点存在错误前提或证据不足时，Skill 会先指出问题，再提供更窄、更可靠的表达，而不是一味迎合。

## 适用场景

你可以向它提供：

- 一个知乎问题或候选问题列表
- 一篇回答草稿、文章草稿或已有回答
- 一段行业判断、争议观点或项目复盘
- 真实的个人经历和零散素材
- 账号定位、选题规划或内容分发需求

默认输出顺序为：

1. 诊断结论
2. 诊断依据
3. 修改策略
4. 完整修改稿
5. 分发建议

如果你只需要成稿，可以在请求中明确说明。

## 工作流程

```text
选题判断
  → 问题匹配
  → 开头钩子
  → 观点密度
  → 结构
  → 论证
  → 知乎调性
  → 个人辨识度
  → 标题或回答形态
  → 发布策略
```

当任务涉及具体知乎问题的关注者、浏览量、回答数、近期活跃或平台规则时，应先联网核验。无法核验的信息应明确标记为“未核验”或“—”，不能用相邻指标代替。

## 在 Codex 中使用

将仓库克隆到个人 Skills 目录：

```bash
git clone https://github.com/hhhggg136/zhihu-content-doctor.git ~/.codex/skills/zhihu-content-doctor
```

在新任务中使用：

```text
$zhihu-content-doctor

请诊断下面这篇知乎回答，先指出问题，再给出完整修改稿和分发建议：
……
```

也可以直接描述需求；在支持自动发现 Skills 的环境中，系统可根据任务内容调用它。

## 接入豆包模型

这个 Skill 更适合通过 **火山方舟 AgentKit + 豆包模型** 使用，不应表述为“普通豆包 App 可以直接导入”。

适配步骤：

1. 保留 `SKILL.md` 和 `references/` 目录。
2. 将它们放入名为 `zhihu-content-doctor` 的根文件夹并压缩为 ZIP。
3. 在火山方舟 AgentKit 的 Skills 中心创建自定义 Skill。
4. 将 Skill 发布到指定的 Skills 空间。
5. 在使用豆包模型的 Agent 中添加并启用该 Skill。
6. 若要判断知乎实时热度，同时配置网页搜索或链接读取能力。

`agents/openai.yaml` 用于 Codex/OpenAI 的界面元数据，AgentKit 版本可以不包含该文件。

具体控制台入口和字段可能随平台更新，请以[火山方舟 AgentKit 官方文档](https://www.volcengine.com/docs/86681/2205064)为准。

## 使用示例

### 诊断已有草稿

```text
请使用知乎内容医生诊断这篇草稿。
重点检查它有没有答非所问、公众号腔和证据不足的问题。
先诊断，再给修改稿。
```

### 选择回答还是文章

```text
我有一篇关于 TikTok 内容电商的长文。
请判断它更适合回答已有知乎问题，还是作为独立文章发布。
如果要借已有问题流量，请先联网核验候选问题的当前数据。
```

### 拆分不同载体

```text
把这个母题分别改成知乎回答版、知乎文章版和朋友圈引言。
不要只是机械缩短，要按各自的阅读场景重新组织。
```

## 文件结构

```text
zhihu-content-doctor/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── diagnosis-and-voice.md
    └── distribution-and-formats.md
```

- `SKILL.md`：角色、触发场景、工作流程和输出规则
- `diagnosis-and-voice.md`：诊断维度、证据分层和文风标准
- `distribution-and-formats.md`：问题匹配、回答/文章选择和多载体分发
- `openai.yaml`：Codex/OpenAI 环境的展示信息

## 内容边界

- 不编造用户经历、身份、ROI、GMV、成交或传播结果
- 不把单一案例直接写成行业规律
- 不把浏览量、回答数和关注者数量混为一谈
- 不因问题流量高就建议硬塞旧文章
- 不把草稿已准备好表述为已经发布
- 不代替用户完成未经授权的公开发布
