# 问题匹配、载体与分发

## 先回答还是先发文章

默认先检查是否存在可借力的已有问题，但“已有流量”不是充分理由。

| 维度 | 适合回答 | 适合文章 |
|---|---|---|
| 题目匹配 | 核心结论直接兑现问题 | 需要提出自己的完整命题 |
| 读者意图 | 读者正在寻找该判断 | 读者需要被重新定义问题 |
| 改写成本 | 大部分材料可围绕题目重组 | 必须扭曲原稿才能塞进去 |
| 内容寿命 | 问题长期有效或近期仍活跃 | 主题独立、可持续引用 |
| 账号资产 | 能强化目标标签且不重复 | 可作为母题、系列或代表作 |
| 竞争 | 有差异化切口和进入空间 | 高饱和问题下难以获得注意 |

结论选项应明确：

- **优先回答**：问题高度匹配，改写后能直接解决读者期待。
- **回答 + 文章双轨**：回答承担一个窄判断，文章承载完整框架；两者不能原文复制。
- **优先文章**：现有问题会扭曲命题，或所有高流量候选都答非所问。
- **暂缓**：证据不足、定位冲突或当前没有值得进入的问题。

## 当前问题数据核验

涉及具体知乎问题流量或热度时：

1. 打开问题详情页或可靠的公开页面，记录核验日期。
2. 分别核对关注者、浏览量、回答数、近期回答/编辑活动；不可互相替代。
3. 搜索结果摘要只能用于发现候选，不作为最终指标证据。
4. 无登录态或页面不可见时，写“未核验/—”，说明限制。
5. 热度判断是综合推断，要写出依据；不要把单个快照包装成趋势。

推荐候选时至少说明：问题名称、已核验信号、题目匹配、建议切口、竞争/错位风险。不要仅因数字最大就推荐。

## 多载体重构

同一母题共享核心事实与主判断，但每种载体重新设计入口和密度。

### 知乎回答版

- 入口：直接回应问题，可用一个现场或反常识判断。
- 范围：只解决题目承诺，不展示完整知识体系。
- 结构：结论前置，围绕 2–5 个关键判断展开，加入条件和反例。
- 目标：让读者获得一个更好的判断，并愿意关注该账号的稳定视角。

### 知乎文章版

- 入口：提出独立命题，解释为什么值得讨论。
- 范围：允许搭建完整框架、案例链和多方观点。
- 结构：可形成母题、系列或可长期引用的专业资产。
- 目标：沉淀账号代表性内容，而非仅承接一个问题页的需求。

### 朋友圈引言

- 入口：一句真实困惑、争议或写作缘起。
- 范围：只交代核心判断和为什么值得点开，不复述全文目录。
- 结构：问题 → 核心判断 → 阅读价值/链接。
- 目标：促成合适的人阅读，而不是用夸张承诺换点击。

### 其他载体

若用户要短视频口播、公众号、播客简介等，先判断其阅读/观看情境、时长、互动方式和行动目标，再重构；不能把知乎稿机械删字。

## 分发建议模板

- **主载体**：回答 / 文章 / 双轨 / 暂缓
- **理由**：题目匹配、读者意图、账号定位、内容寿命
- **已有问题机会**：问题名 + 当前核验数据 + 日期 + 证据限制
- **建议切口**：这次只回答哪个窄问题
- **可拆版本**：文章、回答、朋友圈等各自承担什么
- **风险**：答非所问、证据不足、过度重复、热点衰减或定位稀释
